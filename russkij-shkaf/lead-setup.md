# Настройка приёма заявок

## Звонки Gudok.tel в MAX

Приёмник `public/gudok-webhook.php` использует того же бота и тот же чат MAX, что и формы в `mail.php`. Он отправляет отвеченные и пропущенные звонки (включая занятый номер), телефон клиента, время по Москве, длительность, источник, регион и ссылку на запись, если она есть. Повторная отправка того же ID звонка в рамках проекта после успешной доставки не создаёт новое сообщение, пока сохранён файл состояния во временной папке сервера.

1. Загрузите production-сборку `dist` на PHP-хостинг, включая обновлённый `mail.php` и новый `gudok-webhook.php`.
2. Секрет уже задан в `public/gudok-webhook.php`; настройка окружения не требуется. При необходимости переменная PHP `GUDOK_WEBHOOK_TOKEN` переопределяет встроенный секрет.
3. В Gudok откройте настройки проекта → Уведомления → Вебхуки. Включите вебхуки и выберите метод POST.
4. Укажите `https://russkij-shkaf.ru/gudok-webhook.php?token=fe9adef743d3051d49cd7ce30e8452b5997b9537a2a98d53`. Если рабочий домен отличается, замените и домен.
5. Протестируйте отправку в Gudok, затем сделайте отвеченный и пропущенный звонок. Проверьте оба сообщения в чате «Заявки Русский шкаф».

Поддерживаются JSON, POST-поля и GET. Приёмник сообщает об успешной доставке HTTP 200; при недоступности MAX — 502, при недоступности хранилища состояния — 503, при неверном секрете — 403. Автоматические повторные попытки со стороны Gudok в документации не описаны: не рассчитывайте на гарантированную доставку при сбоях. Временная папка PHP должна быть доступна для записи; файлы `gudok-call-*.state` нельзя очищать, если нужно сохранять защиту от повторов.

Документация: https://gudok.tel/help/obschie-voprosy/vebhuki_webhook

Сайт отправляет все формы POST-запросом на `/mail.php`. Приёмник отправляет заявку на почту, в Telegram и в MAX; файлы из формы сравнения смет и приложенные фотографии передаются вместе с сообщением.

## Требования к хостингу

- Размещение должно поддерживать PHP 8 или новее и запуск PHP-файлов из корня сайта.
- PHP должен поддерживать `mail()` для отправки почты. Расширение cURL желательно для отправки сообщений и файлов в мессенджеры; для текстовых запросов есть fallback через `file_get_contents()`.
- При публикации через Vite файл `public/mail.php` копируется в корень `dist`. Веб-сервер должен исполнять его как PHP, а не отдавать исходный код.

## Переменные окружения на сервере

Задайте значения в панели хостинга или в окружении PHP-FPM. Не добавляйте секреты в `VITE_*`, HTML, JavaScript или Git.

- `LEAD_RECIPIENT_EMAILS` — адрес или адреса получателей, через запятую.
- `MAIL_FROM_EMAIL` — адрес отправителя на домене сайта; если не задан, используется `no-reply` текущего домена.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_CHAT_ID` — числовой ID целевого Telegram-чата.
- `MAX_BOT_TOKEN` — токен MAX-бота.
- Числовой ID чата MAX «Заявки Русский шкаф» уже задан в `public/mail.php`.

Добавьте ботов в нужные чаты и убедитесь, что им разрешено отправлять сообщения. Для почты проверьте, что хостинг разрешает `mail()` и домен отправителя настроен у почтового провайдера.

Журнал без содержимого заявок и файл защиты от повторов хранятся во временной папке сервера, вне публичной папки сайта.
