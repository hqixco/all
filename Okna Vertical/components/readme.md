# Компоненты страниц

Цены в карточках при сборке дополняются общим компонентом `card-installment.html`: платёж равен цене, делённой на 36 месяцев, с округлением вверх до целого рубля. Суммы вручную не дублировать. Генератор `scripts/card-installments.mjs` пересчитывает их из основной цены и не добавляет повторные плашки. Проверка: `node scripts/check-card-installments.mjs`.

Разметка типовых блоков находится в `components/*.html`, данные — в `seo-pages/components/*.js`. Рендерер `scripts/components.mjs` работает только при генерации сайта и записывает готовый HTML. В браузере работают только обработчики взаимодействий.

Главная использует те же шаблоны через `scripts/sync-home-components.mjs`. Комментарии `component:...` отмечают управляемые области `index.html`: содержимое этих областей обновляется при сборке. Править их нужно в шаблонах и данных, а не в сгенерированном HTML.

## Блоки

| Ключ страницы | Компонент | Данные |
| --- | --- | --- |
| `hero` | `hero` | Заголовок, описание, фон, преимущества, карточки |
| `company` | `company` | Общий блок главной и страницы компании: тексты, адрес офиса, маршрут и галерея из `company.js` |
| `choice` | `quiz` | Заголовок, массив `questions`, тексты формы |
| `cases` | `cases` | Массив кейсов, `photos`, позиции `details`, категория и фильтры |
| `solutions` | `products` | Карточки `items`, характеристики `features`, цена и настройки попапа |
| `price` | `included` | Изображение сметы, строки `items`, условия |
| `process` | `installation` | Вкладки `walls`, данные `wallDetails`, схема и пояснения |
| `warranty` | `warranty` | Строки гарантии и пояснения |
| `reviews` | `reviews` | Каталог `reviews.js`: отзывы `items`, чип `topic`, категории, изображения, источники |
| `faq` | `faq` | Массив `items` с вопросами и ответами; из него строится FAQ Schema |
| `calculator` | `calculator` | Тексты, варианты количества, размеры, места установки, ценовая модель |
| `related` | `related` | Карточки `items`: изображение, заголовок, описание, ссылка |

`footer`, `photo-modal` и `gallery-modal` — общие компоненты. Шапка и карта сайта уже собираются функциями `headerMarkup` и `footerMenuMarkup` в `scripts/sync-header.mjs`. Модальные окна присутствуют в HTML сразу.

## Новая страница

1. Добавить SEO-метаданные и маршрут в `seo-pages/data.js`.
2. Создать файл данных в `seo-pages/components/` и зарегистрировать его маршрут в `index.js` этой папки.
3. Указать `prefix`, исходное `heroImage`, `order`, настройки `sections` и данные `footer`.
4. При необходимости задать `navigation`: массив `{ section, label, icon? }`. Якоря шапки выводятся из `id` выбранных секций; ошибочная ссылка останавливает сборку.
5. Запустить `npm run build` и `npm run check:components`.

Каждая запись `sections` имеет вид `{ component: 'products', data: {...} }`. Порядок берётся строго из `order`. Оформление и поведение берутся из общего компонента; копировать HTML или CSS под маршрут не нужно. Для другого набора секций меняется только `order`. Если блока нет в `order`, его контент не выводится.

```js
export const page = {
  prefix: 'house',
  heroImage: 'hero-house.webp',
  order: ['hero', 'choice', 'cases', 'solutions', 'price', 'process',
    'warranty', 'reviews', 'faq', 'calculator', 'related'],
  sections: {
    hero: { component: 'hero', data: heroContent },
    choice: { component: 'quiz', data: quizContent },
    // Остальные записи — по той же схеме.
  },
  footer: footerContent,
};
```

`prefix` даёт секциям уникальные классы `house-hero`, `house-choice` и т. д. Вложенные элементы сохраняют общие классы. Полный рабочий пример — `apartment.js`; текущая главная — `home.js`.

Все 23 подстраницы зарегистрированы в `seo-pages/components/index.js`. Товарные страницы используют фабрику данных `service-pages.js`, настройки маршрутов и карточек лежат в `catalog.js`. Фабрика переиспользует структуру данных модели квартиры; HTML не копируется. Для индивидуальных изменений страницы меняйте её настройки и данные, а не сгенерированный `index.html`.

Информационные страницы задаются в `information.js`, тексты юридических документов — в `legal.js`. Дополнительные общие компоненты: `content` для информационных карточек, `document` для разделов документов, `consultation` для запроса расчёта без неподтверждённой цены. Если нет исходной цены для системы, вместо оконного калькулятора выводится консультация. Фон, карточки, фото кейсов и квиза оптимизируются сборщиком со стабильными именами `component-*.webp`.

Дополнительные проверки: `node scripts/check-page-models.mjs` проверяет все страницы, компоненты, якоря и ассеты; `node scripts/check-page-layouts.mjs` проверяет 10 ширин; `node scripts/check-page-interactions.mjs` проверяет квизы, монтаж, галереи, калькуляторы, локальные формы и страницы без JavaScript. Браузерным проверкам нужен `npm run preview -- --host 127.0.0.1` на порту 4173.

## Калькулятор

`countOptions` — массив `{ value, labelHtml, checked }`; один вариант должен быть выбран. `widthRange` и `heightRange` задают `min`, `max`, `step`, `value`. `widthLabelHtml`, `heightLabelHtml` и `countQuestionHtml` меняют подписи. `installationPlace` фиксирует тип объекта; пустая строка и массив `places` выводят выбор объекта. Идентификаторы ползунков выводятся из `id` компонента.

Необязательный `model` переопределяет `basePrice`, базовые размеры, множители количества и объекта, цены монтажа, доставки, демонтажа и вывоза. Та же функция считает начальную цену на этапе сборки и обновляет её в браузере. Каждый экземпляр формы работает в своём контейнере.

## Шаблоны и поведение

`{{field}}` экранирует значение; `{{{fieldHtml}}}` вставляет доверенную разметку из данных проекта. `{{#items}}...{{/items}}` выводит коллекцию или условную область. Значения с суффиксом `Html` могут содержать короткую внутреннюю разметку. Принудительные переносы строк запрещены: текст переносится естественно по доступной ширине; структурный HTML блока держать в шаблоне. Если обязательного поля нет, сборка выдаёт ошибку с именем компонента и поля.

Квиз берёт вопросы из JSON внутри своей секции. Галереи используют заранее отрисованные кнопки и миниатюры. Монтажные вкладки и калькулятор имеют общие обработчики в `src/components/`. Имена страницы не используются для выбора поведения новых компонентов.

Изменения оформления вносить в общие стили. Новые исключения с префиксом страницы добавлять только при реальном отличии компонента. Ассеты сохраняют стабильные описательные имена.
